# 研修講師が「自分のための道具箱」を作ったら、29個の魔法書になった話

友季子です。
「面白きこともなき世を面白く」を合言葉に、研修づくりをしています。

今日は、ここ最近こつこつ作りためてきた**29個のツールを1つにまとめた「統合ジェネレーター」**について書きます。何ができて、どういう発想で作っているのか、同じように研修や現場で奮闘している方に届けば嬉しいです。

---

## きっかけは「毎回おなじ作業」をしていたこと

研修の現場では、毎日のように似た作業が発生します。日報を整える、確認テストを作る、サブの先生に依頼書を書く、議論の進行を考える……。一つひとつは大したことがなくても、積もると地味に時間を食います。

そこで「自分が繰り返している作業を、入力するだけで形になる道具にしてしまおう」と思い立ちました。最初は日報ツール1つでしたが、作るたびに「これも欲しい」が増えていき、気づけば29個になっていました。

せっかくなので、全部を1つの画面から開けるようにまとめたのが、この統合ジェネレーターです。起動すると、羊皮紙風の目次（魔法書のイメージです）が開いて、そこから各ツールを呼び出せます。

---

## どんな思想で作っているか

全ツールに共通している、私なりのこだわりが3つあります。

ひとつ目は、**完全オフラインで動くこと**です。すべて1枚のHTMLファイルにまとまっていて、外部のサーバーにもCDNにも接続しません。入力したデータが外に送られることはありません。研修で扱う情報はセンシティブなことも多いので、ここは最初から譲れない条件でした。

ふたつ目は、**「AIあり／なし」を選べること**です。多くのツールに、Anthropic APIキーを入れれば自動生成してくれる版と、キーがなくても手動プロンプトをコピーして使える版を用意しました。キーがない環境でも、生成されたプロンプトを手元のAIに貼り付けてJSONを戻せば、同じ結果が得られます。

みっつ目は、**相手に合わせて説明を変えること**です。文系・理系、新卒・第二新卒、基礎クラス・応用クラス。同じ内容でも、相手によって響く伝え方は違います。だから多くのツールで、対象者を選ぶと言葉づかいやたとえが切り替わるようにしています。

---

## 29個のツール、ざっくり地図

数が多いので、使う場面ごとにグループで紹介します。

### 📋 日々の記録・報告まわり

研修や現場の「毎日」を支えるツールたちです。

- **日報ジェネレーター**：その日の記録と報告を、整った形で。
- **報連相・敬語（あり／なし）**：カジュアルな伝え方を、ビジネスの言い回しに整えます。敬語の練習にも。
- **業務受領**：依頼を受けるときの確認事項を漏れなく。
- **業務委譲・交渉（あり／なし）**：仕事を上手に振る・お願いするための言い方を組み立てます。

### 📝 教える・問いを作るまわり

研修講師としての本丸です。

- **作問スタジオ**：問題を作る工房。
- **試験・クイズ作成（あり／なし）**：クラス（基礎／応用）・受講生の背景（文系/理系×新卒/第二新卒）・到達レベル（覚える→説明できる→応用できる）に合わせて、**口頭試問・筆記試験・プチ理解度クイズ**を作ります。
- **開発工程の教え方（あり／なし）**：要求定義→要件定義→実装→テストを新卒に教える教材です。**文系にはホットケーキ作りのたとえ**（「ふわふわなのが食べたい」という願い＝要求、レシピと分量＝要件、焼く＝実装、味見＝テスト）で、**理系には原理原則のみ**で説明を切り替えます。
- **30分説明タイマー**：説明を「導入→概要→要点→説明→正式には→補足」の6段階に時間配分して、話しきる練習・本番に。
- **説明台本（あり／なし）**：その6段階に沿った説明台本を作ります。

### 🎤 場をつくる・進めるまわり

- **ファシリ・議論サポート（あり／なし）**：議論の進行台本・問いかけ集・役割分担を用意し、**議論タイマー**で時間を管理、最後に**結論・決めたこと・宿題**を「学級だより」風にまとめます。学校の黒板をイメージしたデザインにしました。
- **サブ講師依頼**：サブの先生への依頼と引き継ぎを、抜け漏れなく工程化します。

### 🛠 設計・上流・現場まわり

- **IT現場ジェネレーター**：作業手順と報連相の段取りを。
- **品質保証ジェネレーター**：要件と品質のチェック表を（Excelでも出せます）。
- **IT業務設計**：要件工学の考え方で業務を設計、図解も。
- **要求定義ナビ**：上流工程の進め方の道しるべ。
- **ふわふわ指示変換**：あいまいな指示を、具体的な仕様に翻訳します。
- **Web制作STUDIO**：公開前チェックなどを。
- **Jiraタスク作成**：課題を整理してチケットの形に。

### 💬 AIと上手につきあうまわり

- **プロンプト先生（あり／なし）**：プロンプトの書き方を一緒に考えます。
- **ITコンサル法人練習（あり／なし）**：法人クライアント向けの商談を練習する道具です。**業界別の典型課題テンプレ**（製造・小売・金融・医療など8業界）、**費用感を「幅」で示す提案の型**、そして**英語商談モード**（日本語／英語／対訳）も入れました。

### ✍️ 発信するまわり

- **Zenn風記事テンプレ**：「やってよかったこと」記事と「気づき・次に活かせること」記事のひな形に加え、**Qiita／Zennの投稿ヘッダー**と、折りたたみ・脚注・数式などの**記法スニペット集**まで。この記事も、こうしたツールで骨組みを作っています。

## 作ってみて気づいたこと

正直に言うと、最初から壮大な計画があったわけではありません。「目の前のひと手間を減らしたい」を積み重ねただけです。

ただ、数が増えてから振り返ると、いくつか見えてきたことがありました。

ひとつは、**ツールを作る過程そのものが、教材研究になっていた**こと。「文系の人にどう説明すれば伝わるか」を考えてツールに落とし込むと、自分の理解も整理されました。ホットケーキのたとえも、そうやって生まれたものです。

もうひとつは、**「AIなし版」を必ず用意したことが効いた**こと。APIキーがなくても、手動でプロンプトをコピーすれば誰でも使えます。配る相手の環境を選ばないのは、研修の現場では大きな利点でした。

そして、**1枚のHTMLで完結する身軽さ**。インストール不要、ネット接続不要で、ファイルを開けば動く。この手軽さが、結局いちばん長く使われる理由になっている気がします。

---

## おわりに

29個と聞くと多く感じるかもしれませんが、どれも「自分が困ったこと」から生まれた、ささやかな道具です。全部を使う必要はなくて、刺さるものが1つでもあれば嬉しいです。

同じように、教える側・現場を回す側で奮闘している方の、ちょっとした時短や気持ちの余裕につながりますように。

面白きこともなき世を、少しでも面白く。

うさうさエンジニア研究室🐰　石黒 友季子
